# Моите задачи

Курсов проект по „Мобилни приложения“ · ФН 2401321025 · репо `MobileApps2025-2401321025`

## Идея

„Моите задачи“ е Android приложение за лични задачи (to-do списък). Потребителят записва какво
има да свърши, задава приоритет и краен срок, отбелязва готовите задачи и ги търси и филтрира.
Когато няма идея какво да си запише, приложението може да изтегли предложение за задача от
интернет чрез REST заявка.

## Как работи

Приложението има едно Activity с два екрана (фрагмента), между които се преминава с
Navigation Component.

**Екран „Списък“**

- Показва всички задачи от локалната база данни. Незавършените са най-отгоре, подредени по
  приоритет и най-близък краен срок.
- Цветната лента вляво показва приоритета (зелено – нисък, оранжево – среден, червено – висок).
  Просрочените задачи са с червен надпис „Просрочена“.
- Отметката до задачата я отбелязва като завършена (заглавието се зачертава).
- Чиповете „Всички / Активни / Завършени“ филтрират списъка, а лупата в лентата търси по
  заглавие и описание.
- Плъзгане на задача наляво или надясно я изтрива; за няколко секунди се показва „Отмени“.
- От менюто „Изтрий завършените“ се чистят всички готови задачи наведнъж.
- Бутонът **+** отваря екрана за нова задача, а натискане върху задача я отваря за редакция.

**Екран „Нова задача / Редакция“**

- Полета: заглавие (задължително, до 80 знака), описание, приоритет и краен срок (избира се
  от календар).
- Бутонът „Предложи ми задача (от интернет)“ прави GET заявка към
  `https://dummyjson.com/todos/random` и попълва заглавието с получения текст. При липса на
  интернет се показва съобщение за грешка.
- „Запази“ записва задачата в базата и връща към списъка. При празно заглавие се показва грешка
  под полето и нищо не се записва.
- При редакция в лентата има кошче за изтриване на задачата (с потвърждение).

**Данни.** Всичко се пази в Room (SQLite) база `tasks.db` на устройството, така че задачите
остават и след затваряне и рестартиране на приложението. Интернет е нужен само за бутона с
предложението.

| Операция | Къде в UI |
|----------|-----------|
| Create   | бутон **+** → „Запази“ |
| Read     | списъкът, търсене, филтър |
| Update   | натискане върху задача → „Запази“; отметката „завършена“ |
| Delete   | плъзгане, кошчето в редакцията, „Изтрий завършените“ |

## Архитектура

MVVM с Repository слой, написано на Java.

```
UI (View)            MainActivity, TaskListFragment, TaskEditFragment, TaskAdapter
   │  наблюдава LiveData, подава действията на потребителя
ViewModel            TaskListViewModel, TaskEditViewModel
   │  не познава Android View-та; работи само през интерфейса TaskRepository
Repository           TaskRepository (интерфейс) → DefaultTaskRepository
   ├── Room          AppDatabase, TaskDao, Task        (локална база)
   └── Retrofit      TodoApi, TodoDto                  (REST заявка)
Domain               TaskValidator, TaskFilter, DueDates (чиста Java логика)
```

- **Пакети:** `data/local`, `data/remote`, `data`, `domain`, `ui/list`, `ui/edit`, `di`.
- **Dependency injection:** ръчно, през `AppContainer`, който се създава в `TasksApp`
  (Application). Той прави базата, Retrofit клиента и Repository-то и ги подава на
  ViewModel-ите чрез `ViewModelFactory` (constructor injection).
- **Нишки:** записите в базата минават през отделен `Executor`, а резултатите се връщат на
  главната нишка. Списъкът се обновява сам, защото Room връща `LiveData`.
- **Lifecycle:** състоянието (търсене, филтър, избран срок) е във ViewModel и оцелява при
  завъртане на екрана. ViewBinding се нулира в `onDestroyView`, за да няма memory leak.
- **UI:** Material 3 (`Theme.Material3.DayNight`), светла и тъмна тема според системата,
  динамични цветове на Android 12+.
- **Permissions:** само `INTERNET` (за REST заявката).

Технологии: Java 17, min SDK 24, target SDK 37, Room, Retrofit + Gson, Navigation Component,
ViewModel + LiveData, Material Components, JUnit 4, Mockito, Espresso.

## Потребителски поток

1. Стартиране → екран „Списък“ (празен при първо пускане).
2. Натискане на **+** → екран „Нова задача“.
3. Въвеждане на заглавие (или „Предложи ми задача“), избор на приоритет и срок → „Запази“.
4. Връщане в списъка – новата задача се вижда.
5. Отметка → задачата е завършена; чип „Активни“ я скрива.
6. Натискане върху задача → редакция → „Запази“ или кошчето за изтриване.
7. Плъзгане на задача → изтриване, с възможност за „Отмени“.
8. Затваряне и повторно отваряне на приложението → задачите са запазени.

## Стъпки за стартиране

Изисквания: Android Studio (с вградения JDK) и Android SDK Platform 37.

1. Клониране:
   ```bash
   git clone https://github.com/<потребител>/MobileApps2025-2401321025.git
   ```
2. В Android Studio: **File → Open** и се избира папката на проекта. Изчаква се Gradle sync.
3. Избира се емулатор или свързан телефон (Android 7.0+) и се натиска **Run ▶**.

От команден ред:

```bash
./gradlew assembleDebug            # компилира debug APK
./gradlew testDebugUnitTest        # unit тестове
./gradlew connectedDebugAndroidTest  # Espresso UI тестове (нужен е емулатор/телефон)
./gradlew createDebugUnitTestCoverageReport  # отчет за покритието
./gradlew assembleRelease          # release APK
```

**Тестове.** 42 unit теста покриват валидацията, филтъра, датите, Repository-то и двата
ViewModel-а (около 21 % от редовете на целия код, включително UI класовете). Espresso тестът
`AddTaskFlowTest` проверява основния сценарий: добавяне на задача и появата ѝ в списъка.
